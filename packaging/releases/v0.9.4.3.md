# Spellcross Reloaded v0.9.4.3

Windows x64 maintenance release based on the stable 0.9.4.2 executable source commit [`7038920`](https://github.com/luboshorak/spellcross-reloaded/commit/703892091bda7df69b9babe20877e31597d4c7cc), plus targeted fixes [`3b5b89e`](https://github.com/luboshorak/spellcross-reloaded/commit/3b5b89ea410a4e66e267ebeba8192939a9f17b6d). This is **not** a merge from the later `main`.

## Unit purchasing and re-arm (#120)

- Offer UDES type 36 normally; suppress its folded-turret tactical configuration type 35 from the strategic shop.
- Also suppress airborne Mobile Infantry type 8 and fortified Destructor type 73 from the strategic shop/re-arm lists, without removing their original transformations, missions or save support.
- Keep Radar 1R and 2R as separately purchasable models. Original scenario/enemy types are excluded, mod-added types remain subject to regular eligibility checks.

## Convoy and escape objectives (#122)

- Restore crossed target markers on the tactical map and minimap, including hidden objective tiles, without revealing regular terrain, units or START deployment squares.
- Fall back to the original `CIEL` artwork when `TARGET` is unavailable.

## Confirmed original mechanics (#123)

- No change: Hi-Tech Infantry has no applicable technology upgrades in the original `UPGRADES.DEF`.

## Build and packaging

- Windows FileVersion / ProductVersion: **0.9.4.3**; release label/tag: `0.9.4.3` / `v0.9.4.3`.
- Package names: `Spellcross_Reloaded_v0.9.4.3.zip` and optional WinRAR SFX `Spellcross_Reloaded_v0.9.4.3.exe`.
- Release builder now diagnoses uninitialized editor submodules, auto-selects an installed MSVC toolset (including `v143` on VS 2022), and writes verbose MSBuild logs to `dist/build-logs/`.
- Reuse the 37 manifest-verified fallback videos directly from the previous `Spellcross_Reloaded_v0.9.4.2.zip` with `-MovieSource`, or let the script find that ZIP under `dist/`. The video files are not added to Git.
- `BUILD-INFO.txt` continues recording Git commit, version and binary checksums; the packager warns about tracked uncommitted source modifications.

## Validation before publication

Automated source/Windows checks verify the unit variant rules, marker rendering rules, version metadata and PowerShell syntax. A complete Windows release build and a manual CZ/EN gameplay smoke test remain necessary before tagging and publishing.
